Recently I have been experimenting with different neural network architectures that use BERT-style embeddings. LLMs are good general purpose models but there are some deficiencies:

  • They are expensive (both in terms of time and money)
  • You build in a dependency on an external API (e.g., OpenAI, Anthropic)
  • They are huge models and their level of complexity often isn’t needed

For many applications smaller models such as different variants of BERT are more suitable. They are small, cheap, open source and can be deployed in your own environment. The challenge is then to figure out how to train them.

In this post I describe some experiments using BERT models for domain-specific NLP tasks including multi-class text classification and named entity recognition. An additional complication is that I have to work in a databricks environment. This can lead to some weird errors when training models.

Some key questions I wanted to understand were:

  • What are some templates for fine-tuning and pre-training BERT models for different tasks?
  • How can I estimate the training time for a given size model, dataset and hardware specifications?
  • How can I optimise the training using different tricks and libraries, particularly when working with multi-GPU compute?
  • What are the idiosyncracies of databricks and how do they come into play?

What is BERT?

How can I use this model?

A simple example is to generate text embeddings. Unlike models such as Word2Vec and GLoVe, that encode text at the token level, BERT embeddings are able to encode richer structure by generating embeddings for the text as a whole. Well, Word2Vec and GLoVe can do this too but often it involves pooling the bag of embeddings for the text. Token-level embeddings struggle with polysemy, that is words that are written the same but can have different meanings. Whereas BERT can use the surrounding context of the sentence to generate a suitable embedding.

Pre-training, full fine-tuning and partial fine-tuning

BERT models are large, maybe not by the standards of today’s LLMs, but they are usually of the order of a 100 million parameters. This means that training and scaling become more significant hurdles, compared to your classical machine learning models. There are three related concepts when training BERT models (or many other large neural nets): pre-training, full fine-tuning and partial fine-tuning. These involve what proportion of the parameters in the model we choose to train.

Pre-training

Pre-training is where you use an enormous unlabelled dataset of text, with the objective being ‘Masked Language Modelling’. You can easily create labels for text from unlabelled text through the task of guess the missing word. So you essentially removes part of each chunk of text and treat the missing parts as labels that need to be predicted by the model.

Once you have a neural net architecture for language models, you can then do this from scratch, which takes a long time (e.g., days). The end result is a generic model that has learned a rich set of structures in written text, including semantic, syntax, and higher level meaning.

The end result is a model like BERT-base-uncased available on huggingcase. Example: embed some text and compare the similarity of the embeddings

As we see it does a pretty good job of clustering together sentence of similar meaning and distinguishing those that are different. It also handles spelling errors, differences in syntax and synonyms. One immediate challenge is that it isn’t so good at nuances within a specific domain. This is because it has been trainied on a large amount of generic text, rather than a specific set.

If we have a specific domain such as biomedical or mental health, how can we then adapt our model? The answer is fine-tuning

Finetuning

In fine-tuning the original model is kept but we provide additional training data and update the weights using this data. We can think of this as ‘tweaking’ the weights slightly.

This can still be slow, however, since we are updating all the weights in the model (all 100 million or so). But a large amount of work in pre-training was done to get the model to a point of understanding existing linguistic structures, and we only need to learn additional vocabularly and context. So adjusting all weights seems like overkill.

Partial fine-tuning

Instead we can ‘freeze’ most of the layers of the neural network, and instead only update a few, for example the final four. The training process is then significantly sped up without much of an impact on performance..
